# Предложение по схеме: приготовление взбиванием (матча)

Ответ на задание оркестратора от 2026-11-06 (inbox #2): «Матча готовится
взбиванием, а не проливами: предложи расширение модели данных, со ссылками на
источники».

`data/teas.json` и `types/tea.ts` я не меняю — схему вносит отдельный агент.
Дополняет [`schema-proposal.md`](./schema-proposal.md) (там 9 предложений по
остальной схеме) и опирается на [`raw/jp-matcha-preparation.md`](./raw/jp-matcha-preparation.md).

## Почему модель вообще надо менять

Это не вопрос удобства — текущая модель физически не может описать матчу.

| Поле `BrewMethod` | Для матчи |
|---|---|
| `ratio` (г/100 мл) | работает |
| `temperature` | работает |
| `infusions[]` — список **проливов** с временем каждого | **не работает: пролива нет ни одного** |

У матчи нет настаивания и нет отделения листа: порошок взбивают в воде и пьют
целиком. `infusions: [{number: 1, time: 15}]` описывал бы «первый пролив
длительностью 15 секунд», чего не происходит.

Нормативное основание — ISO/TR 21380:2022, п. 4.2:

> «The liquor is prepared by **whisking the powder in freshly boiled water** and
> remains in a **suspended state without agglomeration or sedimentation**.»

И п. 3.1 того же документа требует «**fine grinding process** for the leaf to make
tea powder». То есть и форма продукта (порошок), и способ приготовления
(взбивание) закреплены стандартом.

## Предложение

### 1. Новый вид способа приготовления

```ts
export type BrewMethodType =
    | "gongfu" | "western" | "grandpa" | "cold-brew" | "iced"
    | "whisked";   // взбивание: матча
```

Если будет принято предложение 7 из `schema-proposal.md` (разделение
дегустационных и потребительских режимов), `whisked` получает
`purpose: "consumer"`.

### 2. Отдельная форма описания вместо `infusions`

```ts
/** Приготовление взбиванием: матча. ISO/TR 21380:2022 */
export interface WhiskedPreparation {
    /** Стиль: усуча (薄茶, тонкий) или коича (濃茶, густой) */
    style: "usucha" | "koicha";
    /** Навеска порошка, г */
    powder: number | Range;
    /** Объём воды, мл */
    water: number | Range;
    /** Температура воды, °C */
    temperature: Range;
    /** Движение: взбивание до пены или вымешивание до однородной массы */
    motion: "whisk" | "knead";
    /** Длительность, с — если источник её указывает */
    duration?: number | Range;
    /** Целевой результат — то, что описывает источник */
    target?: string;
    /** Просеивать ли порошок перед приготовлением */
    sift?: boolean;
    /** Инструмент */
    tool?: "chasen" | "electric-frother" | "shaker";
}

export interface BrewMethod {
    // ...
    /** Для type: "whisked". Взаимоисключимо с infusions */
    whisked?: WhiskedPreparation[];
    infusions?: { number: number; time: number | Range; notes?: string }[];
}
```

`infusions` становится опциональным: у `whisked` его нет, у остальных — есть.
Это не ломает существующие записи, потому что все восемь чаёв каталога его имеют.

### Почему `style` — отдельное поле, а не два чая

Усуча и коича — **один и тот же продукт**, приготовленный по-разному:
концентрация отличается в 4–5 раз. Делать из них два `slug` неправильно —
получится, что это разные чаи. Делать один набор параметров тоже нельзя —
2,4 г/100 мл и 13,3 г/100 мл не усредняются.

### Почему `motion` важен

В японском это **разные глаголы**: усучу 点てる (взбивать), коичу 練る
(вымешивать). У усучи цель — мелкая пена, «как крем»; у коичи — густая
однородная масса **без пены**. Если не различить, пользователь будет взбивать
коичу венчиком и не получит нужной текстуры.

## Значения для записи матчи

| Поле | Усуча | Коича |
|---|---|---|
| `style` | `"usucha"` | `"koicha"` |
| `powder` | `{from: 1.7, to: 2}` г | `4` г |
| `water` | `{from: 60, to: 80}` мл | `30` мл |
| `temperature` | `{from: 75, to: 85}` °C | `{from: 75, to: 85}` °C |
| `motion` | `"whisk"` | `"knead"` |
| `duration` | — (до результата) | `15` с |
| `target` | «мелкопузырчатая пена на поверхности, как крем» | «густая однородная масса без пены» |
| `sift` | `true` | `true` |
| `tool` | `"chasen"` | `"chasen"` |
| в пересчёте `ratio` | 2,4–3,3 г/100 мл | 13,3 г/100 мл |

### Источники каждого значения

| Значение | Источник | Уровень |
|---|---|---|
| взбивание, взвесь без осадка | ISO/TR 21380:2022 п. 4.2 | **A** |
| порошок, var. sinensis, в тени, без скручивания | ISO/TR 21380:2022 п. 3.1 | **A** |
| усуча 1,7 г / 70–80 мл / ~80 °C, просеивать | Платформа удзитя (Киото) | B |
| усуча 2 г / 60 мл / 80 °C | Ippodo (Киото, с 1717) | B |
| коича 4 г / 30 мл / 80 °C / 15 с вымешивания | Ippodo | B |
| «пена как крем» у усучи | Платформа удзитя | B |

⚠ **Температура 80 °C — уровень B, не A.** ISO говорит «freshly boiled water»
(свежекипячёная), конкретной температуры не задаёт. Диапазон 75–85 °C в таблице —
моя интерпретация двух источников, указавших «80 °C» и «80 °C前後» (около 80).
Если нужна строгость, ставить `{from: 80, to: 80}` и помечать `confidence: medium`.

## Что ещё меняется из-за матчи

### `ratio` перестаёт быть сопоставимым между способами

13,3 г/100 мл у коичи рядом с 2,2 г/100 мл у сенчи в одной колонке выглядит как
ошибка, хотя оба верны. Если в интерфейсе есть сортировка или сравнение по
`ratio`, матчу надо либо исключать, либо показывать отдельной группой.

Для сравнения — весь разброс по каталогу после добавления матчи:

| Чай | г / 100 мл | Источник |
|---|---|---|
| сенча обычная | 2,2 | префектура Сидзуока, A |
| ISO 3103 (эталон) | 2,0 | ISO 3103, A |
| улун по GB/T 23776 | 4,5 | GB/T 23776, A через вторичный |
| гёкуро | 16,7 | префектура Сидзуока, A |
| **матча усуча** | **2,4–3,3** | B |
| **матча коича** | **13,3** | B |

Разброс — восьмикратный, и это нормально. Единого «правильного» ratio не бывает.

### `characteristics.liquorColor` у матчи означает другое

У матчи нет «цвета настоя»: это суспензия, а не настой. Поле либо оставить с
пометкой, что описывается цвет взбитого напитка, либо не заполнять.

### Фотография

`photo` у матчи логичнее показывать взбитой в чаше, а не сухим листом — сухой лист
у неё порошок, и на фото неотличим от любого другого зелёного порошка.

## Если расширять модель не хотят

Минимальный вариант без новых типов: оставить `infusions` с одним элементом,
`time` = длительность взбивания, и описать всё остальное в `notes[]`. Это
сработает технически, но запишет в поле «время пролива» то, что проливом не
является, и потеряет различие усуча/коича. **Не рекомендую**: матча — не частный
случай настаивания, а другой способ, и спрос на неё, по данным justea-market,
выше, чем на любой сорт из текущего каталога.
