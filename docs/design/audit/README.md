# UX/UI-аудит justea.ru

Дата: 6 ноября 2026. Агент: justea-design.
Снято с `pnpm dev` (Next.js 16.1.1) на коммите `edbd683`, Chromium 1247 (Playwright 1.62).
Вьюпорты: desktop 1440×900, tablet 820×1180, mobile 390×844 (DPR 2).
Темы: светлая и тёмная.

[«Как перепроверить»](#как-перепроверить).

## Коротко

Сайт держится на одной сильной идее — ярко-зелёный фон, крупная Bainsley,
китайские цифры проливов — и она работает. Проблемы не в идее, а в том, что
слой интерфейса под ней не достроен: **фокус-кольца удалены глобально**,
**границы всех карточек и кнопок ниже порога контраста**, **таймер проливов не
подаёт сигнала об окончании пролива**, **тёмная тема теряет бренд**, а
**фотографий чая нет ни на одном экране**, хотя поле `photo` в данных есть.

Серьёзность: **Блокер** — ломает основной сценарий или закрывает доступ целой
группе пользователей; **Высокая** — сценарий проходится, но с ощутимой потерей;
**Средняя** — заметный изъян качества; **Низкая** — шлифовка.

Колонка «Статус» отражает состояние после PR «a11y-фундамент» (ветка
`agent/design`). «Починено» — проверено скриптом или на скриншоте «после»
в [`after/`](./after/); «в редизайне» — решается при переработке экранов,
после выбора направления.

## Блокеры

### 1. Фокус-кольца удалены глобально

`app/globals.css` содержит два правила, которые гасят индикацию фокуса на всём
сайте:

```css
*:focus { outline: none !important; }
* { outline: none !important; }
```

Проверка: четыре нажатия Tab на главной — ни одного видимого индикатора
([`shots/d-focus-ring.png`](./shots/d-focus-ring.png)). Программно:
`getComputedStyle(link).outlineStyle === "none"`, `boxShadow === "none"` —
замены кольцу нет.

Это нарушение WCAG 2.1 **2.4.7 Focus Visible** (уровень AA). Практический
эффект: пользователь клавиатуры и скринридера не может понять, где он
находится; ни один интерактивный элемент сайта не даёт обратной связи на
фокус. `!important` на `*` вдобавок делает невозможным локальное исправление —
любой `focus-visible:ring-*` в компоненте будет перебит.

**Чинится** удалением обоих правил и введением единого токена фокуса
(`:focus-visible` с кольцом в 2–3 px и достаточным контрастом к обоим фонам).
Это первое, что нужно сделать в дизайн-системе.

### 2. Таймер не сообщает об окончании пролива

Машина `steep-timer.ts` по истечении времени уходит в `betweenSteeps` и оттуда
в `paused` со следующим проливом. Ни звука, ни вибрации, ни вспышки, ни
уведомления — экран просто меняет цифру и замирает.

Сценарий, ради которого сайт существует, — «поставил таймер, отвернулся,
наливаешь чай». Сейчас за таймером нужно следить глазами, иначе пролив
перестоит. Плюс: нет Wake Lock, поэтому на телефоне экран гаснет посреди
пролива; состояние не переживает переключение метода и уход со страницы.

**Чинится** на уровне дизайна+кода: звук/вибрация в конце пролива (с
переключателем и уважением к «без звука»), крупная визуальная смена состояния,
Screen Wake Lock на время работы таймера.

### 3. Выбор объёма воды ломает вёрстку и невидим в тёмной теме

При фокусе на поле объёма (`BrewRatio` → `VolumeSelect` → `VolumeInput`):

- строка «5 гр на 100 мл» разваливается — текст «гр на» и «мл» пропадает,
  иконка весов остаётся одна, «100» уезжает на новую строку
  ([светлая](./shots/d-volume-dropdown-light.png),
  [тёмная](./shots/d-volume-dropdown-dark.png));
- выпадающий список фиксированно покрашен в `bg-main-200` (`#d9f6c9`), а текст
  наследует `--foreground`. В тёмной теме это `#ededed` на `#d9f6c9` —
  контраст ≈ 1.1, пункты физически не читаются;
- список открывается вниз и обрезается нижней границей экрана;
- кнопка-переключатель закомментирована, список открывается только по фокусу,
  Escape не закрывает, роли `listbox`/`option` нет;
- у `<input>` нет доступного имени (в скане — `<INPUT> ""`), размер 34×30 px;
- в `VolumeInput.tsx:22` остался `console.log(value)`.

Пересчёт пропорции — вторая по важности функция после таймера, и сейчас она
нерабочая в тёмной теме и визуально сломанная в светлой.

## Высокая серьёзность

### 4. Границы всех элементов ниже порога контраста

WCAG 2.1 **1.4.11 Non-text Contrast** требует 3:1 для границ элементов
управления. Фактические значения на фирменном зелёном `#9cd37a`:

| Токен | Контраст | Порог 3:1 |
|---|---|---|
| `border-black/10` (карточки чая, таймер) | **1.24** | не проходит |
| `border-black/20` (таблетки фильтров, круглые кнопки) | **1.56** | не проходит |
| `border-black/40` (hover-состояние) | **2.62** | не проходит |

В тёмной теме так же: `border-white/10` — 1.25, `border-white/20` — 1.77;
проходит только `border-white/40` (3.77).

Отсюда и визуальное ощущение: карточки на главной как будто плавают без
опоры, рамка таймера еле угадывается, hover почти не читается
([`shots/d-home-light.png`](./shots/d-home-light.png)). Это не вкусовщина, а
измеримый дефект.

### 5. Тёмная тема — это другой сайт

Светлая тема: фон `#9cd37a`, бренд повсюду. Тёмная: фон `#0a0a0a` — то есть
обычный чёрный шаблон Next.js, от бренда не остаётся ничего, кроме двух
кислотно-зелёных колонн рекламных заглушек `#7db95c` (контраст к фону **8.45** —
самое яркое пятно на экране) ([`shots/d-home-dark.png`](./shots/d-home-dark.png),
[`shots/d-tea-dark.png`](./shots/d-tea-dark.png)).

Тёмная тема должна быть той же системой с другой яркостью: тёплый тёмный фон с
зелёным подтоном, зелёный — в акцентах, а не в заглушках.

### 6. Фотографий чая нет ни на одном экране

В `data/teas.json` поле `photo` заполнено у `longjing` и `assam`, файлы лежат в
`public/teas/`. Ни `TeaCard`, ни страница чая не выводят `<img>` — скан выдал
`imgs: []` на всех страницах. Вместо фото — плашка цвета настоя
(`liquorColor`) с иконкой листа по центру.

Побочный эффект: иконка листа `black/40` на цвете настоя не проходит контраст
ни на одном чае — 1.68 (Ассам), 2.12 (Да Хун Пао), 2.71 (Лунцзин), 2.80 (Бай
Хао). А сама плашка на фирменном зелёном даёт 1.22 у Лунцзина — карточка
сливается с фоном.

Цвет настоя — хорошая находка, но как **дополнение** к фото, а не замена.
Справочник по чаю без фотографий листа и настоя проигрывает любому конкуренту.

### 7. На мобильном главное действие уехало на третий экран

390×844, страница чая ([`shots/m-tea-light.png`](./shots/m-tea-light.png)): до
первого полезного параметра заваривания нужно проскроллить хлебные крошки, тип,
заголовок, происхождение, описание, аромат, вкус, послевкусие, заголовок метода
и его описание. Температура и пропорция появляются примерно на 1300 px от
верха, таймер — около 1600 px, то есть на третьем экране.

Человек приходит на страницу с чайником в руках. Сейчас он сначала читает
эссе. Параметры заваривания и таймер должны быть в первом экране или в липкой
панели.

### 8. Модалка поиска не держит фокус и не управляется клавиатурой

Панель поиска (`role="dialog" aria-modal="true"`) не реализует ловушку фокуса —
Tab уводит за пределы диалога в страницу под ним. Результаты не перебираются
стрелками, Enter не открывает выделенный чай — доступна только навигация
Tab'ом по всем карточкам подряд. `aria-expanded` стоит на инпуте, но без
`aria-controls`, и роль `combobox` не объявлена.

Для компонента, который открывается на весь экран и является главной точкой
входа в каталог, это существенно.

Отдельно: анимация раскрытия `clip-path` длиной 500 мс не учитывает
`prefers-reduced-motion`.

## Средняя серьёзность

### 9. Два разных поиска для одной задачи

Один и тот же запрос показывается двумя разными интерфейсами с двумя разными
карточками: модалка (`SearchTeaCard` — фото-плашка слева, дескрипторы-чипсы) и
страница `/search` (`TeaCard` — крупная плашка сверху, обрезанное описание)
([панель](./shots/d-search-panel.png), [страница](./shots/d-search-results.png)).
На странице `/search` нет ни фильтра по типу, ни сортировки, которые есть в
модалке. Нужно выбрать одну модель.

### 10. Рекламные заглушки: зелёное на зелёном и кислотное на чёрном

`BlockAdvertisement` в светлой теме даёт контраст 1.34 к фону — колонки по
краям выглядят не как рекламное место, а как дефект рендеринга. В тёмной теме
та же заливка становится самым ярким объектом страницы (8.45). Нижний баннер на
странице чая — последнее, что видит пользователь, и это пустой прямоугольник.

На 1440 px контент заперт в 670 px, по краям ~385 px с каждой стороны отданы
невидимым заглушкам. Либо реклама — реальный продукт и её надо спроектировать,
либо на широких экранах эта площадь должна работать на контент.

### 11. Один пролив выглядит как поломка

`/assam` ([`shots/d-assam-single.png`](./shots/d-assam-single.png)): «Западный
стиль» — один настой. Таблица проливов рисует одинокое `一` и под ним `240 сек`,
а таймер показывает `4:00 сек`. Две разные записи одного числа на одном экране,
причём `4:00 сек` — просто неверно (подпись «сек» прибита к значению
`formatSteepTime`, которое отдаёт `мм:сс`).

Половина каталога (ассам, дарджилинг, сенча в западном стиле) заваривается
одним настоем, и для них весь блок спроектирован не под них.

Там же: переключатель методов прячется при одном методе, а их один у 7 чаёв из
8 — то есть сценарий «а как ещё можно заварить» на сайте почти не существует,
хотя это сильная сторона справочника.

### 12. Мелкий служебный текст не проходит контраст

| Где | Токен | Контраст | Порог |
|---|---|---|---|
| Метки секций в поиске («ВСЕ ЧАИ», «Найдено: N») | `black/50`, 13 px | **3.50** | 4.5 |
| Разделители хлебных крошек | `black/40` | **2.62** | 4.5 |
| Тёмная тема, подписи | `white/40` | **3.77** | 4.5 |

Проходят: `black/70` (6.45), `black/60` (4.74), `white/70` (9.71),
`white/60` (7.30), `white/50` (5.33). Основной текст — `#000` на `#9cd37a` —
даёт 12.01, это отлично; проблема только в полупрозрачных оттенках ниже 60 %.

Чипсы дескрипторов в модалке поиска — 11–12 px, это ниже разумного минимума
даже там, где контраст формально проходит.

### 13. Цели касания мельче 44 px

WCAG 2.2 **2.5.8** просит минимум 24×24, iOS HIG и Material — 44×44 / 48×48.
Фактически:

| Элемент | Размер |
|---|---|
| «В избранное» на карточке | **32×32** |
| Кнопки таймера (старт/пауза/пропуск/сброс) | **36×36** |
| Поле объёма воды | **34×30** |
| Переключатель темы | 40×40 |
| Таблетки фильтра по типу | высота 40 |
| Ссылки хлебных крошек | высота 21 |

Кнопки таймера — самое больное: по ним жмут мокрыми руками рядом с чайником.

### 14. Нет шапки, подвала и логотипа

Скан landmarks: `header: 0, footer: 0`. Шапка — это строка поиска и кнопка
темы, без логотипа и без ссылки на главную. С любой внутренней страницы
вернуться домой можно только через хлебные крошки (а на `/search` и 404 их
нет). Подвала нет вообще — некуда положить «о проекте», контакты, ссылку на
церемонии, юридическое.

## Низкая серьёзность

### 15. Порядок заголовков нарушен (h3 раньше h2)

Страница чая: `h1` → `h3 Аромат` / `h3 Вкус` / `h3 Послевкусие` → `h2 Гунфу-ча`.
Для скринридера структура выглядит как провал уровня и возврат. «Аромат/Вкус/
Послевкусие» должны быть `h2`, либо весь блок нужно обернуть в секцию со своим
`h2`.

### 16. Подсказка «можно менять :)» скрыта именно там, где нужна

`BrewInfo` отдаёт стрелку-подсказку только с `sm:` и выше. На мобильном
остаётся подчёркнутое «100» без объяснения — выглядит как случайное
подчёркивание, а не как редактируемое поле. При этом на десктопе подсказка
занимает блок в 60 px и оставляет под собой большую пустоту между колонками
([`shots/d-tea-light.png`](./shots/d-tea-light.png)).

### 17. Мелочи качества

- `line-clamp-2` рубит описания карточек посреди слова: «известный вкусом,
  напоминающим…», «Сильная ферментац…».
- 404: ссылка «Вернуться на главную» без подчёркивания до наведения — не
  опознаётся как ссылка; страница-тупик без подсказок, что искать дальше
  ([`shots/d-404.png`](./shots/d-404.png)).
- Плейсхолдер в модалке поиска обрезается о кнопку закрытия («…аромату, вкусу»
  упирается в край) ([`shots/m-search-panel.png`](./shots/m-search-panel.png)).
- У поля поиска нет кнопки очистки.
- Секции «Недавние» и «Избранное» на главной рендерятся пустыми, без
  объясняющего состояния.
- `console.log(value)` в `VolumeInput.tsx:22`.
- `--text-lg: 24px` объявлен в `@theme`, но ни один компонент не использует
  шкалу — везде произвольные `text-[36px]`, `text-[44px]`, `text-[19px]`.
  Типографической шкалы де-факто нет.

## Что работает хорошо и стоит сохранить

- Фирменный зелёный с чёрным текстом — 12.01 по контрасту, это сильно выше
  требований AA и редкость для цветного фона.
- Bainsley в крупных кеглях — узнаваемо и уместно; Comfortaa на цифрах
  отделяет данные от текста.
- Китайские цифры проливов `一二三四五六` — лучшая деталь макета, это сразу
  задаёт тему.
- Модалка поиска на мобильном (структура: инпут → фильтры → результаты)
  удобна; ей не хватает доступности, а не замысла.
- Цвет настоя как признак чая — хорошая идея, нужно вернуть её как акцент при
  живом фото.
- Переключение темы, избранное и недавние уже есть — каркас для личного
  сценария заложен.

## Как перепроверить

Скрипты аудита (снимок экранов и расчёт контраста) лежат вне репозитория, в
каталоге задачи. Воспроизводится так:

```bash
pnpm install && PORT=3010 pnpm dev
# снимки
BASE=http://localhost:3010 OUT=./shots PLAN=./plan-audit.json node shot.mjs
# контраст
node contrast.mjs
```

Расчёт контраста — формула WCAG 2.1: относительная яркость по
`0.2126·R + 0.7152·G + 0.0722·B` с гамма-коррекцией sRGB, отношение
`(L₁+0.05)/(L₂+0.05)`. Полупрозрачные токены (`black/50` и т. п.) сначала
смешиваются с фоном.

## Что уже починено

Направление визуального стиля ещё не выбрано, но часть находок от него не
зависит — они вынесены в отдельный PR «a11y-фундамент» и сделаны до выбора.
Стиль сайта при этом не менялся: это починка, а не редизайн.

| Что | Как проверено |
|---|---|
| Кольцо фокуса вместо `outline: none !important` | `getComputedStyle(link).outlineStyle` стало `solid`, ширина 3 px (было `none`) ([скриншот](./after/after-d-focus-ring.png), [на таймере](./after/after-d-focus-timer.png)) |
| Токены границ и приглушённого текста с проверенным контрастом | `--line` 3.27:1 и `--muted` 4.97:1 на зелёном; 3.49:1 и 9.07:1 на тёмном |
| Сигнал в конце пролива: звук, вибрация, переключатель | Web Audio без файла-ассета; Wake Lock на время работы таймера |
| Выбор объёма воды | строка больше не разваливается, список читается в тёмной теме и открывается вверх ([светлая](./after/after-d-volume-light.png), [тёмная](./after/after-d-volume-dark.png)) |
| Цели касания 44 px | избранное и кнопки таймера пропали из списка «меньше 44 px» в скане |
| Порядок заголовков | стало `h1 → h2 → h2 → h2 → h2` |
| Ловушка фокуса в модалке поиска, `prefers-reduced-motion` | Tab больше не уходит за пределы диалога |
| `console.log` в `VolumeInput` | удалён |
| Подсказка про объём на мобильном | добавлена словами там, где стрелка не помещается |

рекламные блоки, типографическая шкала.
