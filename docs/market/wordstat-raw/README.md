# Сырые данные и как они собраны

Собрано 2026-11-06 агентом justea-market. Серверное время по заголовку HTTP `Date`
(`google.com`): `Fri, 06 Nov 2026 19:18:36 GMT`. Локальные часы машины спешат на ~21 минуту,
поэтому таймстампы внутри `suggest-raw.jsonl` (локальный `time.time()`) сдвинуты вперёд
на эту величину — для относительных интервалов это неважно, для датировки берите 2026-11-06.

## Файлы

| Файл | Содержание |
|---|---|
| `suggest-raw.jsonl` | 10 260 ответов API подсказок: по строке на запрос. Поля: `engine`, `group`, `seed`, `part` (что отправляли), `suggestions` (что вернулось, в исходном порядке), `ts`. При ошибке вместо `suggestions` — `error`. Ошибок: 0 |
| `suggest-aggregated.json` | 16 477 уникальных фраз: `query`, `hits` (в скольких выдачах встретилась), `avg_pos` (средняя позиция, 0 = первая), `engines`, `groups`, `seed_count` |
| `google-trends-raw.json` | сырые ответы widget-API Google Trends, 13 срезов. У каждого среза `keywords`, `geo`, `timeframe`, `data` (по виджетам), `errors` |
| `google-trends-derived.json` | выжимка: средний уровень, тренд за период, сезонный индекс по месяцам, топ-регионы, related queries (топ и растущие) |
| `google-trends-summary.txt` | та же выжимка в читаемом виде |
| `google-trends-spb.json` | доп. срезы: сезонность церемонии отдельно по СПб и Москве, подарочный спрос. По городам выборка Google слишком мала (средний уровень 0,8 по СПб) — пригодны только подарочные ряды |
| `wordstat-shows.jsonl` | Вордстат: по строке на вызов `getTable`. Поля: `seed`, `region_id`, `region`, `period_start/end`, `query_invalid`, `has_next_page`, `rows` (до 200 фраз с точными показами в месяц) |
| `wordstat-graph.jsonl` | Вордстат: месячная динамика за 2 года по головным фразам. `monthly` — список `{year, month, shows}`, месяц 1-индексный (в сыром ответе API он 0-индексный, скрипт поправляет) |
| `wordstat-frequencies.csv` | все снятые фразы с частотами по СПб / Москве / России и пометкой, есть ли фраза в ядре |
| `wordstat-seasonality.csv` | сезонные индексы по месяцам, пик и провал для каждой головной фразы |
| `wordstat-shows-badseeds.bak` | отбракованный первый прогон: сиды были длинными фразами и отдавали по 0–14 строк вместо 200. Оставлен как напоминание, в расчётах не используется |

## Как собирался сид-лист

180 сид-фраз в 8 группах (`../scripts/seeds.py`): типы чая, сорта, заваривание, посуда,
церемония, здоровье, коммерция, общая справка. Источники сидов: `data/teas.json` (8 сортов
каталога), `docs/tea-catalog-candidates.json` (340 кандидатов), `docs/tea-brewing-science-ru.md`,
плюс узнаваемые рыночные формулировки.

Каждый сид расширялся префиксами:
- сам сид;
- сид + 8 вопросных слов (`как`, `что`, `сколько`, `какой`, `чем`, `где`, `почему`, `зачем`);
- сид + 6 маркеров (`купить`, `цена`, `отзывы`, `польза`, `рецепт`, `своими руками`);
- сид + каждая из 27 букв алфавита — **только для Яндекса** (у Google это расширение не делалось,
  чтобы не упереться в лимиты).

Итого 7 560 префиксов для Яндекса и 2 700 для Google.

## Важное ограничение

`hits` в `suggest-aggregated.json` — **не частотность.** Это число префиксов, из которых
подсказка всплыла, и оно прямо зависит от того, как построен сид-лист. Сравнивать `hits`
можно внутри одного кластера; между кластерами — нельзя, потому что сидов в группах разное
количество (сортов 45, церемонии 22). Абсолютные частотности появятся только с Вордстатом.

## Как воспроизвести

Скрипты — в `../scripts/`. Нужен только `requests`.

```bash
cd docs/market/scripts
python3 harvest_suggest.py ../wordstat-raw/suggest-raw.jsonl   # ~12 мин
python3 analyze_suggest.py ../wordstat-raw/suggest-raw.jsonl   # -> suggest-aggregated.json
python3 trends.py ../wordstat-raw/google-trends-raw.json       # ~6 мин
python3 trends_retry.py                                        # добор упавших виджетов
python3 trends_derived.py                                      # -> google-trends-derived.json
python3 analyze_trends.py ../wordstat-raw/google-trends-raw.json > ../wordstat-raw/google-trends-summary.txt
python3 build_core.py                                          # -> ../semantic-core.csv
```

`trends_retry.py` и `trends_derived.py` содержат абсолютные пути к файлам этого репозитория —
при переносе поправить константу `RAW`/`ROOT` в начале файла.

## Внутренний API Вордстата: как он был найден и как им пользоваться

Публичного API у Вордстата нет, а страница — SPA: в HTML нет ни одной цифры,
всё подгружается XHR после авторизации. Угадать схему запроса не удалось
(все попытки давали `400 Bad Request`), поэтому контракт снят с живой
страницы: Chromium с куками пользователя открыл обычный URL Вордстата, а
перехват запросов показал, что именно отправляет сам интерфейс.
Скрипт перехвата — одноразовый, в репозиторий не кладу; воспроизводится
любым инструментом, который умеет логировать сетевые запросы страницы.

### Авторизация

Нужны куки `Session_id` и `sessionid2` с домена `.yandex.ru`. Обе помечены
**HttpOnly**, поэтому из консоли браузера (`document.cookie`) их не достать —
нужен экспорт расширением (Cookie-Editor, «Get cookies.txt LOCALLY») или
панель Application в devtools.

**Ловушка при проверке авторизации.** В состоянии страницы есть поле
`"login":""` — оно пустое **и у авторизованной сессии**, это не признак
входа. Настоящий признак — `"displayName":"<имя>"`. Я сначала принял
`login` за индикатор и ошибочно решил, что рабочие куки не работают.

### Запросы

Таблица «Запросы со словами» — точные показы в месяц:

```http
POST https://wordstat.yandex.ru/wordstat/api/getTable
Content-Type: application/json
Referer: https://wordstat.yandex.ru/?region=<id>&view=table&words=<urlencoded>

{"currentDevice":"desktop,phone,tablet",
 "dbname":"rus",
 "filters":{"region":"2","tableType":"popular"},
 "searchValue":"пуэр",
 "startDate":"01.11.2024","endDate":"31.10.2026"}
```

Ответ:

```json
{"table":{"info":{"hasNextPage":true,"page":0,
                  "period":{"startDate":1786222800000,"endDate":1791320400000}},
          "isQueryInvalid":false,
          "tableData":{"associations":[],
                       "popular":[{"text":"пуэр","value":"10649"}, …]}}}
```

Месячная динамика за два года (абсолютные показы):

```http
POST https://wordstat.yandex.ru/wordstat/api/getGraph
{"currentDevice":"desktop,phone,tablet","currentGraphType":"month",
 "dbname":"rus","filters":{"region":"2"},"searchValue":"чайная церемония",
 "startDate":"01.11.2024","endDate":"31.10.2026"}
```

→ `graph.images.timeSeries.preparedValues.absolute` = `[{"year":2025,"month":0,"y":4014}, …]`,
где **`month` 0-индексный** (0 = январь).

Прочие методы того же вида: `getMap` (регионы), `getAllTableData`,
`getMoreTableData` (постраничный добор, поле `phPage`), `search`
(всё сразу — у меня стабильно отдавал 400, не использую).

### Что важно знать

- **`startDate`/`endDate` на таблицу не влияют:** API возвращает свой
  стандартный период, он приходит в `info.period`. В снятых данных это
  **2026-08-08 … 2026-10-06**. Для динамики даты учитываются.
- **`currentDevice` должен быть строкой `"desktop,phone,tablet"`**, а не
  `"all"` — с `"all"` приходит 400.
- **`filters` для таблицы — объект** `{region, tableType}`, регион живёт
  именно там, а не в query-строке. Для графика — `{region}`.
- Один вызов отдаёт **до 200 фраз**, поэтому выгоднее задавать короткие
  головные сиды: «пуэр» даёт 200 строк, «как заваривать да хун пао в
  заварнике» — ноль. На этом я ошибся в первом прогоне (см. `*-badseeds.bak`).
- `tableType: "associations"` («Похожие») у проверенных фраз возвращал
  пустой список.
- Регионы: `2` — Санкт-Петербург, `213` — Москва, `1` — Москва и область,
  `10174` — Петербург и Ленобласть, `225` — Россия.
- Ходить **только с домашнего IP**: сессия создана там, через зарубежный
  прокси Яндекс её оборвёт. В скрипте для этого `Session.trust_env = False`.
- Темп ~1 запрос в 2–4 с. Капчи за весь сбор не было ни разу. Скрипт
  останавливается на `showcaptcha` и капчу не обходит.
- Прогон возобновляемый: уже снятые пары (сид, регион) пропускаются.
- В период сбора Вордстат показывал баннер «Некоторые данные могут быть
  временно недоступны» — на снятых цифрах сбоев не видно (`isQueryInvalid`
  везде `false`), но держите это в голове при сверке.
