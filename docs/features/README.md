# Функции Justea

Раздел агента justea-features: новые функции сайта (задача №7). Первый заход —
пять идей из отчёта конкурентов (`docs/competitors/report.md`, раздел 6), по
порядку: №3 один тап до таймера, №5 режим под мокрые руки, №1 дневник сессий,
№2 экспорт и импорт данных, №9 дегустационные подсказки.

## Локальные данные пользователя

Аккаунтов и сервера нет: всё, что человек накопил, лежит у него в браузере.
Общий ключ — `justea-journal` в `localStorage`, модуль — `lib/journal/`.

| Файл | Что делает |
|---|---|
| `lib/journal/schema.ts` | версия схемы, типы, приведение прочитанного к текущей версии |
| `lib/journal/storage.ts` | чтение, запись, подписка на изменения |
| `lib/journal/brews.ts` | запуски таймера: какой способ и когда |

Схема версии 1:

```json
{
  "version": 1,
  "brews": {
    "<slug чая>": {
      "methodId": "<id способа заваривания>",
      "lastStartedAt": "<ISO-дата последнего запуска>",
      "count": 3
    }
  }
}
```

Правила, которых держимся дальше:

- версия только растёт, старые данные приводятся к новой схеме в `normalizeJournal`;
- разбор не падает на чужих и битых полях: восстановить эти данные неоткуда;
- всё, что попадает в `justea-journal`, должно пережить экспорт и импорт (идея №2);
- `meta.rating` из каталога в функциях не используется (решение пользователя).

## Идея №3 — один тап до таймера

Что сделано:

- запуск таймера с первого пролива кнопкой «Заварить» в начале блока
  заваривания (`app/components/features/QuickBrewButton.tsx`), не нужно
  прокручивать страницу до блока таймера;
- сайт запоминает, каким способом человек заваривал этот чай, и в следующий раз
  открывает страницу сразу на нём;
- секция «Заварить снова» на главной
  (`app/components/features/BrewAgainSection.tsx`) — ссылки на чаи, которые
  человек действительно заваривал, с параметром `?start=1`;
- `?start=1` на странице чая запускает таймер сразу после загрузки.

«Заваренным» считается запуск таймера, а не открытие страницы: список
«Заварить снова» — про чай, который пили, а не про тот, на который нажали из поиска.

### Что замечено по ходу

На собранном приложении клиентские эффекты страницы чая включаются заметно
позже загрузки: состояние из `localStorage` (избранное, запомненный способ,
`?start=1`) появляется через несколько секунд. Замер на `localhost`,
production-сборка, Chrome 156 через Playwright: первый эффект — 5,7 с на
тёплой загрузке и 14,9 с на холодной; медленных запросов при этом нет
(DOMContentLoaded 2,1 с, load 4,2 с). Это не следствие правок этого раздела —
так же ведут себя избранное и «недавно просмотренные» на текущем `master`.
Передано оркестратору для justea-design.
