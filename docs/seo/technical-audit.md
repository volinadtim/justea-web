## 2. Критичные находки

### 2.1 Нет canonical ни на одной странице — **fixed**

**Было.** В `app/layout.tsx` и `lib/metadata.ts` не было `alternates.canonical`.
`metadataBase` сам по себе canonical не выводит — это только база для
разрешения относительных URL.

Проверка на проде:

```
$ curl -s https://justea.ru/ | grep -c canonical
0
```

**Почему это важно.** `https://www.justea.ru/` отдаёт **200**, а не редирект
(см. 2.2), так что каждая страница доступна минимум по двум адресам. Без
canonical выбор основного URL отдан на усмотрение краулера.

**Стало.** `createPageMetadata()` всегда выставляет `alternates.canonical`.
Корень — `https://justea.ru` без завершающего слэша: именно так Next.js
нормализует URL через `metadataBase`, и в том же виде адрес уходит в sitemap и
в `@id` структурированных данных. Сверка «символ в символ» здесь не
придирка: `…/justea.ru` и `…/justea.ru/` для краулера — два разных URL.

### 2.2 `www.justea.ru` отдаёт 200 вместо редиректа — **handoff → оркестратор (инфраструктура)**

```
$ curl -s -o /dev/null -w '%{http_code} -> %{redirect_url}\n' https://www.justea.ru/
200 ->
```

В `infra/nginx/host-justea-ssl.conf` оба домена обслуживаются одним
`server_name justea.ru www.justea.ru` без разделения. Полный дубль сайта.

Canonical из 2.1 проблему закрывает на 90 %, но правильное решение — 301 с
`www` на основной домен на уровне nginx. **`infra/` не моя зона**, нужен
отдельный PR от владельца инфраструктуры. Предлагаемый блок:

```nginx
server {
    listen 443 ssl http2;
    server_name www.justea.ru;
    # ssl_certificate ... (тот же сертификат, он покрывает оба домена)
    return 301 https://justea.ru$request_uri;
}
```

### 2.3 Нет структурированных данных — **fixed**

На проде ноль блоков `application/ld+json`. Сайт — справочник с рецептами
заваривания, то есть ровно тот контент, под который размечают HowTo; без
разметки он конкурирует в выдаче «как обычный текст».

**Стало.** Новая зона `app/components/seo/`:

| Компонент / функция | Что выводит | Где |
|---|---|---|
| `SiteJsonLd` | `WebSite` + `SearchAction` + `Organization` | `app/layout.tsx`, один раз на сайт |
| `teaTypeListSchema` | `CollectionPage` + `ItemList` (+ `BreadcrumbList`) | главная, `/tea/<type>` |
| `teaPageSchema` | `WebPage` + `BreadcrumbList` + `Article` + `Product` + `HowTo` на каждый способ заваривания | `app/[slug]` |

`HowTo` собирается из реальных данных чая: `supply` — граммовка и температура,
`step` — проливы с `performTime`, `totalTime` — сумма проливов в ISO 8601.

Сознательные решения по честности разметки:

- **Нет `aggregateRating` и `review`.** `meta.rating` в `data/teas.json` — личная
  оценка автора, а не отзывы пользователей. Разметка отзывов без реальных
  отзывов — прямое основание для ручных санкций Google.
- **Нет `offers`.** Чай не продаётся.
- **`meta.origin` не идёт в `countryOfOrigin`.** Это поле ждёт объект `Country`,
  а в данных строка вида «Ханчжоу, Китай» — регион. Положено в
  `additionalProperty` с именем «Регион».
- **Заметки по приготовлению не идут в `HowToTool`.** «Не заливайте кипятком» —
  совет, а не инвентарь; `HowToTool` описывает посуду. Заметки добавлены в
  `description` способа.

`SearchAction` указывает на `/search?q={search_term_string}` — страница закрыта
от индексации (2.5), но как целевой обработчик поиска она работает: это
разные механизмы.

### 2.4 Главная отдавалась динамически, без кеша — **fixed**

```
$ curl -sI https://justea.ru/ | grep -i cache-control
cache-control: private, no-cache, no-store, max-age=0, must-revalidate
```

Причина: `app/page.tsx` читал `searchParams.type`, и Next.js переводил маршрут
в динамический. Каждый обход краулера — рендер на сервере, TTFB вместо отдачи
готового файла.

**Стало.** Фильтр переехал на отдельные маршруты (2.6), `searchParams` с главной
убран, маршрут снова статический:

```
Route (app)
┌ ○ /                 ← было ƒ (Dynamic)
├ ● /[slug]
└ ● /tea/[type]
```

### 2.5 `/search?q=…` открыт для индексации — **fixed**

```
$ curl -s https://justea.ru/search?q=пуэр | grep -c 'name="robots"'
0
```

`?q=` — бесконечное пространство обхода: краулер может генерировать запросы
без конца, расходуя краулинговый бюджет на страницы, которые не должны быть в
индексе. Вдобавок `generateMetadata` ставил в canonical сам поисковый URL с
параметром, то есть легитимизировал каждый такой адрес.

**Стало.**

- `robots: { index: false, follow: true }` — `follow` оставлен, чтобы краулер
  шёл по ссылкам на карточки чая;
- canonical у всех вариантов один — `https://justea.ru/search`;
- `Disallow: /search` в `robots.txt`;
- `/search` убран из sitemap.

### 2.6 Кластеры запросов жили в query-параметре — **fixed**

`/?type=green` нельзя оптимизировать под «как заваривать зелёный чай»: у всех
значений один `<title>`, одно описание и один `<h1>` «Justea».

**Стало.** У каждого типа своя статическая страница `/tea/<type>` со своим
title, description, `<h1>` и вводным текстом (`lib/tea-type-pages.ts`), плюс
`CollectionPage` + `ItemList` в разметке.

Страницы генерируются только для типов, у которых в каталоге есть хотя бы один
чай (`generateStaticParams` + `dynamicParams = false`). Пустая страница типа —
thin content, в индексе ей не место. Сейчас это 4 страницы из 6 возможных:

| URL | Статус | Почему |
|---|---|---|
| `/tea/green`, `/tea/black`, `/tea/oolong`, `/tea/white` | 200, в sitemap | есть чаи |
| `/tea/pu-erh`, `/tea/yellow` | 404 | в каталоге нет ни одного чая этого типа |

Когда justea-sources добавит пуэр и жёлтый чай, страницы появятся сами на
следующей сборке — править код не нужно.

**301 со старых URL** — в новом `middleware.ts`:

```
$ curl -s -o /dev/null -w '%{http_code} -> %{redirect_url}\n' 'http://localhost/?type=green'
301 -> /tea/green
```

Почему middleware, а не `redirects()` в `next.config.ts`: Next.js дописывает
исходный query к destination, и получалось `/tea/green?type=green` — второй URL
с тем же содержимым. Middleware строит адрес сам и параметр выбрасывает.
Неизвестное или пустое значение (`?type=pu-erh`, `?type=bogus`) ведёт на `/`,
а не на 404 — редирект обязан приводить на существующую страницу.

## 3. Высокая серьёзность

### 3.1 390 КБ из 750 КБ шрифтов не используются и при этом предзагружаются — **handoff → justea-design**

Самая крупная проблема Core Web Vitals, и при этом самая дешёвая в починке.
`app/layout.tsx` подключает 4 начертания Bainsley, Geist, Geist Mono и
Comfortaa — 8 файлов woff2, все с `rel=preload` (видно в заголовке `link:`
ответа прода).

| Файл | Размер | Используется в коде? |
|---|---|---|
| `Bainsley_Roman.woff2` | 191 КБ | да (`@apply font-bainsley` в `globals.css:68`) |
| `Bainsley_Bold.woff2` | 192 КБ | да |
| `Bainsley_Italic.woff2` | 168 КБ | **нет** — класса `italic` нет ни в одном компоненте |
| `Bainsley_Bold_Italic.woff2` | 165 КБ | **нет** |
| Geist Sans | 31 КБ | **нет** — `--font-geist` объявлен в `globals.css:28`, класс `font-geist` не встречается |
| Geist Mono | 23 КБ | **нет** — то же для `--font-mono` |
| Comfortaa (2 файла) | ~55 КБ | да (6 компонентов) |

Проверка:

```
$ grep -rn "font-geist\|font-mono\|italic" app/ --include=*.tsx | grep -v layout.tsx
(пусто)
```

**Эффект от удаления:** ~390 КБ меньше предзагрузки на каждой странице, без
единого визуального изменения — эти начертания сейчас физически не применяются
ни к одному элементу.

Шрифты — зона justea-design, поэтому в мой PR правка не входит. Диффа на
~15 строк в `app/layout.tsx` и `app/globals.css` достаточно; готов отдать
отдельным PR по команде оркестратора.

### 3.2 CLS 0.188 на странице чая — **handoff → justea-design**

Порог Google — 0.1. Lighthouse указывает на единственный сдвиг, элемент:

```
div.grid > div.min-w-0 > div.flex > div
```

Это `<div>{children}</div>` в `app/layout.tsx`: контент уезжает вниз, когда
`Suspense`-фallback поиска (`SearchFallback`, `py-3 border-b-2`) заменяется на
реальный `Search`, у которого другая высота. Лечится фиксированной высотой
фallback-а, равной высоте настоящей строки поиска.

На главной сдвига почти нет (CLS 0.028) — там над контентом нет той же
комбинации.

### 3.3 TBT 6420 мс на главной — **handoff → justea-design**

Девять long tasks, из них два по 3.5 с и 2.9 с, оба в клиентском чанке
приложения. На странице чая тот же чанк стоит 763 мс — значит дело не в самом
чанке, а в том, что монтируется на главной: 8 × `TeaCard` (каждая — клиентский
компонент с `FavoriteButton`, читающим `localStorage`), `RecentTeasSection`,
`FavoriteTeasSection` и `Scrollable`/`BodyScrollbars` на overlayscrollbars.

Замеры делались под 4× CPU-throttling Lighthouse на загруженной машине, так что
абсолютные цифры пессимистичны — но разрыв 763 мс против 6420 мс между
страницами на одном чанке реален и указывает на монтирование, а не на размер
бандла.

### 3.4 `lastmod` в sitemap равнялся времени сборки — **fixed**

```
$ curl -s https://justea.ru/sitemap.xml | grep -m3 lastmod
<lastmod>2026-08-30T11:23:00.325Z</lastmod>   ← одинаковая у всех URL
```

В `app/sitemap.ts` стоял `new Date()`. Каждая сборка меняла `lastmod` у всех
URL сразу — краулер перестаёт доверять сигналу и переходит на свой график
обхода.

**Стало.** Дата берётся из данных чая (`meta.addedDate` / `meta.harvestDate`,
максимум из двух). Для главной и страниц типов — максимум по входящим чаям.
Где даты нет, `lastmod` не выводится вовсе: отсутствие сигнала лучше
неверного.

```
<loc>https://justea.ru/longjing</loc>
<lastmod>2024-04-15T00:00:00.000Z</lastmod>
```

### 3.5 OG-картинки заявляли неверный размер — **fixed (частично)**

`lib/metadata.ts` жёстко писал `width: 1200, height: 630` для любой картинки.
Фактически:

| Файл | Реальный размер |
|---|---|
| `public/og.jpg` | 1200 × **800** |
| `public/teas/longjing.jpg` | 1200 × 800 |
| `public/teas/assam.jpg` | 1200 × **1500** |

Соцсети и краулеры верят `og:image:width/height` при построении превью.

**Стало.** Для `og.jpg` выводится реальный размер из `siteConfig`. Для фото
сорта размеры не выводятся вовсе — они разные, и честнее не сообщать размер,
чем сообщить неверный.

**Остаётся для justea-design:** нарисовать `og.jpg` в 1200 × 630 (пропорция,
которую ожидают Telegram, VK и Twitter) — в коде помечено
`TODO(design)` в `lib/site.ts`.

### 3.6 `<h1>` главной — «Justea» — **handoff → justea-voice (через оркестратора)**

Брендовый `<h1>` на главной не работает ни на один небрендовый запрос. По
решению оркестратора поставлен временный вариант с `TODO(voice)`, три варианта
на утверждение — в [`h1-variants.md`](h1-variants.md).

Сейчас в коде (`app/page.tsx`, `HOME_HEADING`):
«Как заваривать чай: проливы, температура, пропорции».

`<h1>` в самом `Hero` не менял — компонент в зоне justea-design; подставить
утверждённый текст нужно будет в обоих местах.

## 4. Средняя серьёзность

### 4.1 Title и description были неинформативны — **fixed**

Было на всех страницах чая: `<title>Лунцзин — Justea</title>`, description —
общее описание сорта. Ни слова из того, что люди на самом деле ищут.

**Стало.**

| Страница | Title | Description |
|---|---|---|
| `/` | `Justea — как заваривать чай: проливы, температура, пропорции` | ключевой запрос + перечисление типов |
| `/tea/green` | `Как заваривать зелёный чай: температура, время, пропорции — Justea` | из `lib/tea-type-pages.ts` |
| `/longjing` | `Лунцзин — как заваривать: проливы, температура, пропорции — Justea` | `Лунцзин: 3.5 г на 100 мл, вода 75–80 °C, 3 пролива.` + описание сорта, обрезка по 160 символам |

Описание страницы чая собирается из данных: сначала конкретика, которую и
ищут (граммовка, температура, число проливов), затем описание сорта. Это
попадает прямо в сниппет выдачи.

Тексты страниц типов — рабочие заготовки под частотные запросы, помечены
`TODO(voice)`: после `docs/market/semantic-core.csv` их должен переписать
justea-voice. Структура полей при этом не меняется.

### 4.2 `robots.txt` не ограничивал ничего — **fixed**

Было `Allow: /` без исключений. Стало — `Disallow: /search`.

`/_next/` сознательно **не** закрыт: Googlebot рендерит страницу и ему нужны
оттуда CSS и JS. Закрыть — получить «заблокированные ресурсы» в GSC и проблемы
с mobile-friendly. Это частая ошибка в шаблонных `robots.txt`.

`Clean-param` для Яндекса не добавлен: индексируемых URL с параметрами больше
нет (`?type=` отдаёт 301), а `robots.ts` в Next.js эту директиву не умеет —
понадобится она только при входящих ссылках с UTM-метками. Помечено
`TODO(seo)` в `app/robots.ts`.

### 4.3 Не было подготовки к подтверждению прав в панелях вебмастеров — **fixed + user**

**Стало.** `app/layout.tsx` выводит мета-теги подтверждения из env:
`NEXT_PUBLIC_YANDEX_VERIFICATION` и `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`.
Пустые значения не выводятся, в репозиторий коды не коммитятся.

Пошаговая инструкция для пользователя — [`webmaster-setup.md`](webmaster-setup.md).

### 4.4 Нарушен порядок заголовков на странице чая — **handoff → justea-design (уже в работе)**

`h1` → `h3` (Аромат / Вкус / Послевкусие) → `h2` (название способа заваривания).
Пропуск уровня мешает и краулеру разбирать структуру, и скринридерам.
justea-design подтвердил, что чинит это в рамках редизайна.
