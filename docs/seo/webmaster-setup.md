# Подключение Яндекс.Вебмастера, Google Search Console и Яндекс.Метрики

Инструкция для пользователя. **Регистрацию, подтверждение прав и установку
счётчиков делает пользователь** — агент не регистрирует аккаунты и не
подтверждает права от чужого имени.

Код на стороне сайта уже готов: мета-теги подтверждения выводятся из
переменных окружения, достаточно вставить значения и задеплоить.

- Домен: `justea.ru`
- Сервер: VPS `89.104.68.81`, деплой — пуш в `master` (GitHub Actions → Ansible → Docker)
- Дата составления: 06.11.2026

## 0. Куда вставлять коды подтверждения

Оба сервиса подтверждают права мета-тегом в `<head>`. Код читает их из env:

| Переменная | Сервис |
|---|---|
| `NEXT_PUBLIC_YANDEX_VERIFICATION` | Яндекс.Вебмастер |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | Google Search Console |

**Локально** (для проверки, что тег появился):

```bash
# в justea-web/.env.local
NEXT_PUBLIC_YANDEX_VERIFICATION=abcdef1234567890
NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION=AbCdEf...
```

**На проде** значение нужно передать в сборку — переменная с префиксом
`NEXT_PUBLIC_` вшивается в бандл на этапе `next build`, то есть задать её в
рантайме контейнера недостаточно. Поэтому:

1. GitHub → репозиторий → Settings → Secrets and variables → Actions →
   **Variables** (не Secrets: код подтверждения не секрет, он виден в HTML) →
   `New repository variable`:
   - `NEXT_PUBLIC_YANDEX_VERIFICATION`
   - `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`
2. Передать их в `deploy.yml` и дальше в `docker build --build-arg` рядом с
   существующим `NEXT_PUBLIC_SITE_URL`.

**Это правка в `.github/workflows/deploy.yml` и `infra/`, то есть вне зоны
justea-seo.** Скажите оркестратору — или, если проще, подтвердите права
альтернативным способом, который деплоя не требует:

- **Яндекс.Вебмастер:** DNS-запись `TXT` в reg.ru (способ «DNS-запись») — ничего
  пересобирать не нужно, работает сразу. **Рекомендую этот способ.**
- **Google Search Console:** тип ресурса **«Домен»** вместо «Префикс URL» —
  подтверждение тоже через `TXT`-запись в DNS, и один ресурс сразу покрывает
  `justea.ru`, `www.justea.ru`, http и https. **Рекомендую этот способ.**

Проверить, что мета-тег доехал после деплоя:

```bash
curl -s https://justea.ru/ | grep -iE 'yandex-verification|google-site-verification'
```

## 1. Яндекс.Вебмастер

Открыть [webmaster.yandex.ru](https://webmaster.yandex.ru/) под тем же
Яндекс-аккаунтом, под которым будет Метрика — тогда счётчик подключится в один
клик.

1. **Добавить сайт.** «+» → `https://justea.ru` (именно https и без `www`).
2. **Подтвердить права.** Вкладка «DNS-запись» → скопировать значение →
   reg.ru → DNS-серверы и управление зоной → добавить запись:
   - Тип: `TXT`
   - Имя/субдомен: `@` (сам домен)
   - Значение: `yandex-verification: <код>`

   Нажать «Проверить». Если DNS ещё не разошёлся — подождать 15–30 минут
   (TTL reg.ru) и нажать снова.

   *Альтернатива:* вкладка «Мета-тег» → код в
   `NEXT_PUBLIC_YANDEX_VERIFICATION` → деплой (см. раздел 0).

3. **Указать главное зеркало.** Индексирование → «Переезд сайта» → убедиться,
   что главное зеркало — `justea.ru` **без** `www`, протокол HTTPS.

   ⚠️ Сейчас `https://www.justea.ru/` отдаёт 200, а не редирект (находка 2.2
   аудита). До правки nginx Яндекс может считать `www` отдельным сайтом.
   Canonical это компенсирует, но зеркало лучше указать явно.

4. **Добавить sitemap.** Индексирование → Файлы Sitemap →
   `https://justea.ru/sitemap.xml` → «Добавить».

   Проверка, что карта отдаётся:
   ```bash
   curl -s https://justea.ru/sitemap.xml | head -5
   ```

5. **Проверить robots.txt.** Инструменты → Анализ robots.txt. Ожидается:
   ```
   User-Agent: *
   Allow: /
   Disallow: /search

   Sitemap: https://justea.ru/sitemap.xml
   ```
   Убедиться, что `/longjing` и `/tea/green` **разрешены**, а `/search` —
   запрещён.

6. **Проверить структурированные данные.** Инструменты → Валидатор
   микроразметки → вставить `https://justea.ru/longjing`. Ожидаются типы:
   `WebSite`, `Organization`, `WebPage`, `BreadcrumbList`, `Article`,
   `Product`, `HowTo` (по одному на способ заваривания).

7. **Регион сайта.** Информация о сайте → Региональность → Россия.
   Для церемоний позже понадобится Санкт-Петербург — но только когда появится
   страница церемоний с подтверждённым адресом.

8. **Переобход страниц.** Индексирование → Переобход страниц → добавить
   вручную `https://justea.ru/` и 4 страницы типов
   (`/tea/green`, `/tea/black`, `/tea/oolong`, `/tea/white`). Лимит — несколько
   десятков URL в сутки, страницы чая Яндекс подхватит из sitemap сам.

**Когда ждать данных:** статистика обхода появляется через 1–3 дня, позиции и
запросы — через 2–4 недели.

## 2. Google Search Console

Открыть [search.google.com/search-console](https://search.google.com/search-console).

1. **Добавить ресурс.** «Добавить ресурс» → тип **«Домен»** → `justea.ru`
   (без `https://` и без `www`).

   Почему «Домен», а не «Префикс URL»: один ресурс покрывает `www` и
   не-`www`, http и https. С учётом того, что `www.justea.ru` сейчас отдаёт
   200 (находка 2.2), это заметно удобнее.

2. **Подтвердить права.** Google покажет `TXT`-запись → reg.ru → DNS-серверы и
   управление зоной → добавить:
   - Тип: `TXT`
   - Имя/субдомен: `@`
   - Значение: `google-site-verification=<код>`

   ⚠️ У `justea.ru` теперь будет две `TXT`-записи на `@` (Яндекс и Google) —
   это нормально и допустимо, не заменяйте одну другой.

   *Альтернатива:* ресурс типа «Префикс URL» → `https://justea.ru` →
   способ «Тег HTML» → код в `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` → деплой.

3. **Добавить sitemap.** Индексирование → Файлы Sitemap → `sitemap.xml` →
   «Отправить».

4. **Проверить URL.** Верхняя строка «Проверка URL» → `https://justea.ru/tea/green`
   → «Проверить опубликованный URL». Смотреть:
   - Статус: «URL есть в Google» или «URL не на Google, можно индексировать»;
   - Блок «Расширенные результаты» — должны появиться `HowTo` и
     «Хлебные крошки»;
   - «Проверить код» → вкладка «Ресурсы» → **не должно быть** заблокированных
     ресурсов из `/_next/` (мы их специально не закрывали в robots.txt).

   Затем «Запросить индексирование» для главной и 4 страниц типов.

5. **Расширенные результаты отдельно.** [Rich Results Test](https://search.google.com/test/rich-results)
   → `https://justea.ru/longjing`.

   ⚠️ Google **отменил** расширенные результаты для `HowTo` в выдаче
   (сентябрь 2023). Разметка остаётся валидной и её читают Яндекс и другие
   потребители schema.org, но в Rich Results Test Google покажет только
   «Хлебные крошки» — это ожидаемо, не ошибка. Для полной проверки графа
   использовать [validator.schema.org](https://validator.schema.org/).

6. **Основные отчёты, куда смотреть потом.**
   - Индексирование → Страницы: сколько в индексе, причины исключения.
     Ожидаемо исключены: `/search` («Исключено тегом noindex»),
     `/tea/pu-erh` и `/tea/yellow` (404 — пока нет таких чаёв в каталоге).
   - Основные интернет-показатели (Core Web Vitals): данные появятся через
     28 дней после начала трафика. Сейчас по лабораторным замерам CLS на
     странице чая 0.188 при пороге 0.1 — ожидается попадание в «Требует
     улучшения», пока justea-design не поправит (находка 3.2 аудита).
   - Удобство просмотра на мобильных.

**Когда ждать данных:** индексирование — 3–14 дней, отчёт «Эффективность» —
через 2–3 дня после первых показов, Core Web Vitals — 28 дней.

## 3. Яндекс.Метрика

1. **Создать счётчик.** [metrika.yandex.ru](https://metrika.yandex.ru/) →
   «Добавить счётчик»:
   - Имя: `justea.ru`
   - Сайт: `justea.ru`
   - Часовой пояс: Europe/Moscow
   - ✅ **Вебвизор, карта скроллинга, аналитика форм**
   - ✅ **Принимать данные только с указанных адресов** — защита от спамного
     трафика на чужой счётчик
2. **Принять условия**, скопировать **номер счётчика** (8 цифр).
3. **Связать с Вебмастером.** В Вебмастере: Настройки → Яндекс.Метрика →
   выбрать счётчик. Тогда в Вебмастере появятся данные о поведении, а в
   Метрике — отчёты по поисковым запросам.

### Установка кода счётчика

Счётчик — это сторонний скрипт в `<head>`/`<body>`, то есть правка
`app/layout.tsx` вне блока metadata. **Вне зоны justea-seo.**

Правильный способ для Next.js — пакет
[`@next/third-parties`](https://nextjs.org/docs/app/guides/third-party-libraries),
либо `next/script` со `strategy="afterInteractive"`, чтобы счётчик не влиял на
LCP и TBT. Номер счётчика — через `NEXT_PUBLIC_YANDEX_METRIKA_ID`.

**Что сделать:** передайте номер счётчика оркестратору — он поставит задачу на
установку (моя зона этого файла не покрывает). Не вставляйте код счётчика
копипастом из интерфейса Метрики: вариант «вставить перед `</head>`»
синхронно блокирует рендер и просадит Core Web Vitals, которые мы только что
замеряли.

⚠️ Счётчик Метрики заметно влияет на TBT. Ставить **после** того, как
justea-design починит находки 3.1–3.3 аудита, иначе не будет понятно, что
именно просаживает производительность.
