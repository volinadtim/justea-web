## Правила пользователя (обязательно)

1. **Интерфейс сайта** — только точечные правки или строгие референсы пользователя (повторять ≥60%). Своих стилей и редизайнов не делать.
2. Пользователь говорит с оркестратором; оркестратор сам общается с агентами и приносит вопросы пачкой.
3. Мерж PR — только после «да» пользователя на конкретный PR.
4. Деньги, публикации, регистрации, письма людям — только после явного «да».
5. Время в данных — по HTTP `Date`.

## Как продолжить на новой машине

```bash
git clone https://github.com/volinadtim/justea-web.git && cd justea-web
git checkout agent/orchestrator
pnpm install
```

Агентам — отдельные worktree на их ветках (`git worktree add ../justea-web-<имя> agent/<имя>`), запускать как вложенные сессии с промптом:
«Ты — justea-<имя>. Прочитай docs/agents/_common.md, docs/agents/<файл>.md, свою переписку docs/orchestrator/mail/inbox/justea-<имя>.md и outbox/justea-<имя>.md (в ветке agent/orchestrator: `git show origin/agent/orchestrator:<путь>`). Продолжай с места остановки. Оркестратор — сессия Justea orchestrator.»

## Порядок мержа PR (проверено 2026-11-07)

Пуш в master = деплой. Мержим только после «да» пользователя, и в этом порядке:

1. **Починки design — одна линейная стопка:** #5 → #7 → #8 → #9 → #10 → #11 → #14. Влить #14 (нумерация проливов) нельзя, не влив #7 и #8, а они меняют вид и ждут решения пользователя. Поэтому design выносит правку `SteepsTable` **отдельным PR от master** — он и нужен раньше всех, иначе данные по пуэрам с 8–10 проливами разведут разметку с видимым контентом на проде.
2. **PR #4 (seo) строго раньше PR #2 (ceremony).** Обе ветки трогают `app/sitemap.ts`, и конфликт опасен тем, что разрешается не глядя: `agent/ceremony` отошла от master и несёт доэтапную карту с `/search` и `lastModified: new Date()` у всех URL — то есть «версия ceremony» вернёт уже закрытые находки 2.5 и 2.6. Проверено: у ceremony это master + 8 строк, у seo — переписанный файл (−13/+45). При конфликте берём версию seo. Остальные общие файлы (`lib/metadata.ts`, `lib/site.ts`, `app/robots.ts`) у ceremony совпадают с master.
3. **PR #15 (www → 301)** — только после `nginx -t` на хосте: ни nginx, ни docker на машине разработки нет, синтаксис проверен структурно.
4. **PR #17 (features, один тап до таймера)** пересекается с починками design только в `SteepTimer.tsx`; перебазировать после того, как определится судьба #7 и #8.
