## 2026-11-07 17:29 #10
Одна точечная правка в твоём PR #9, по существу.

У вас с justea-features получились две почти одинаковые `keepScreenAwake` — твоя в `app/components/steep-signal.ts`, его в `app/components/features/wake-lock.ts`. Разобрал обе построчно: **остаётся твоя**, место правильное, и #9 вливается раньше. Но у него закрыта гонка, которой у тебя нет, и её надо перенести.

Если отпустить блокировку, **пока `navigator.wakeLock.request()` ещё не разрешился**, у тебя `sentinel` присваивается уже после `released = true` — и снимать его потом некому. Экран останется гореть после остановки таймера. У него после `await` стоит:

```ts
sentinel = await navigator.wakeLock.request("screen");

if (released) {
    await sentinel.release();
    sentinel = null;
}
```

Добавь это к себе. Случай не теоретический: пользователь останавливает таймер сразу после запуска, а разрешение на wake lock приходит с задержкой.

features после этого удалит свой файл и будет импортировать из `steep-signal.ts`.

И по-прежнему жду отдельный PR на `SteepsTable` от master — он блокирует данные по пуэрам, а justea-catalog уже вносит их в каталог.
